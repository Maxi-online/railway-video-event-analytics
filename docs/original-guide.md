Пайплайн видеоаналитики с чтением потока, детекцией, трекингом и предметными правилами событий. Kafka и backend-клиент связывают обработку кадров с внешними событиями и конфигурацией опасных зон.

### Воспроизведение и оценка

Для демонстрации используйте разрешённое или синтетическое видео и заранее заданные траектории. Сравнивайте времена и типы событий с разметкой, отдельно измеряйте ложные тревоги в час и задержку. Веса моделей и исходные видео требуют отдельной проверки прав; наличие кода не подтверждает качество на промышленном потоке.

## Установка (локально)
Для установки и разворачивания проекта локально требуется:
1. Убедиться, что на компьютере есть доступ к видеокарте (GPU):
```shell
nvidia-smi
```  

Проверить версии драйверов CUDA и cuDNN:
```shell
nvcc --version
```
Для корректной работы проекта **рекомендуется установить** *CUDA v 12.4*.  
Если драйвера не установлены, требуется их установить!

2. Скопировать файлы проекта к себе на компьютер (через HTTPS или SSH):
```shell
git clone https://github.com/Maxi-online/railway-video-event-analytics.git # HTTPS
git clone portfolio@example.org:ai-team/video_events-ai.git # SSH
```
3. Скачать папку Weights - веса моделей.
- Ссылка на папку Weights: [ссылка](https://example.org/models/model.pt) - выгрузить все веса моделей
  в папку video_events-ai/Weights.
4. Создать виртуальное окружение:
```shell
python -m venv .venv
```
5. Активировать виртуальное окружение:
```shell
.venv/Scripts/activate # Windows
source .venv/bin/activate # Linux
```
6. Установить зависимости (torch + torchvision + общие)
```shell
# Установка torch + torchvision с поддержкой CUDA (GPU)
pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu124
# Установка общих зависимостей (строго после установки torch)
pip install -r requirements.txt
```
7. Запустить проект:
```shell
# Запуск с параметрами по умолчанию (смотрите src/config/config.yaml)
python main.py

# Запуск с переопределенными параметрами
python main.py cam_id=1 lwt_enabled=True r_enabled=True task_1_3_enabled=True task_3_1_enabled=True task_3_3_enabled=True task_4_2_enabled=True task_5_2_enabled=True task_6_1_enabled=True task_6_2_enabled=True task_7_enabled=True task_7_1_enabled=True task_8_1_1_enabled=True task_9_enabled=True task_10_1_enabled=True task_10_2_enabled=True db_enabled=True topic_name=cam_id_1 kafka_address=http://127.0.0.1:29092 kafka_enabled=False save_to_images_temp=False show_video_preview=False
```
8. Чтобы закрыть проект:
- Если show_video_preview=True, то чтобы закрыть cv2 Window - нажмите ESC или q на клавиатуре (en раскладка).
- Если show_video_preview=False, то чтобы закрыть проект - нажмите Ctrl + C - для прерывания с клавиатуры (будут остановлены все потоки)

## Приватная конфигурация

Ключи провайдеров, токены, пароли, прокси и персональные параметры задаются через переменные окружения. `.env.example` содержит имена без значений. Заполненный `.env` и локальные настройки исключены из Git. Не передавайте секреты аргументами команд и не публикуйте реальные журналы, выгрузки, сертификаты или пользовательские документы.

Для запуска экспортируйте нужные переменные в окружение процесса либо заполните игнорируемый локальный `.env`, если используемый entrypoint его загружает. Содержимое `.env` само по себе не становится окружением произвольной Python-команды. Для Docker Compose значения из `.env` передаются в настроенные сервисы.

Hydra/OmegaConf читает секретные поля из `src/config/config.yaml` через `${oc.env:NAME}`.

Имена приватных параметров приведены в [.env.example](.env.example). Старые значения сохранены только в защищённом локальном хранилище владельца; оно не входит в публикуемый проект. После ротации ключей используйте новые значения.

Проверка исходников и формата настроек не заменяет запуск инфраструктуры и оценку модели. Изменения приватности не подтверждают качество AI, работоспособность внешних API или готовность всей системы к эксплуатации.
